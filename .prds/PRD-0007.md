# Summary
A hardening release. M2, the 0.1.0 release and M3 each parked findings that their reviews judged too
small, too unlikely or too late to fix then. They were recorded only in plan ledgers that were
deleted when each milestone finished. This PRD collects them all, checks each against the code as
of v0.2.0, fixes the ones a user can hit plus the cheap hygiene, and records the verdict on every
one, kept or dropped, in its log. It ships as 0.2.1 through `/ship-it`.

# Problem
Five things a user can hit today:
- **Routed TCP stalls behind dead hosts.** `route` holds at most 256 SYNs while their dials run,
  and drops new ones past that. A dial to a host whose firewall drops SYNs takes the relay's
  connect timeout, about 127 s, to fail, and every app retry is a new source port and a new held
  dial. A few retrying clients, or a health checker, fill the cap, and every new routed connection
  stalls for up to two minutes.
- **`ipv6.disable=1`.** On a kernel booted that way, `ip -6 rule show` fails (EAFNOSUPPORT), and
  `route` reads the v6 tables before ssh runs, so it most likely refuses to run at all, v4-only
  targets included.
- **Ctrl-C at the sudo password prompt** ends in `error: sudo exited before the root helper started`
  and exit 1, though the user asked to stop.
- **`forward` hides a remote reset.** The app gets a clean FIN, so a stream the remote cut short can
  look complete to an app that reads to EOF without framing of its own.
- **Offline test runs fail.** Two relay tests look up a `.invalid` name and expect "no such name";
  with no resolver at all (nixpkgs builds, `--network none` containers) the lookup fails
  temporarily instead.

The rest is smaller: a DNS task that panics ends the whole session (none can today), a flow whose
open is slow idles out under a sender that keeps sending, the relay asks more nameservers than libc
would and can't use a link-local one, a CI test that silently skips, an off-by-one between the docs
and the code, duplicated checks, untested branches, and docs that drifted.

# Goals
1. None of the five user-facing problems above remains.
2. Every parked item has a recorded verdict: fixed by a task here, or dropped with a reason.
3. No public signature changes: 0.2.1 is a drop-in for 0.2.0.
4. The workspace declares the oldest Rust it builds on.

# Technical Approach

**T-001, held-dial eviction.** `Stack::held` becomes the SYN plus its dial task's `AbortHandle`,
with a sequence number giving age order (a `BTreeMap<u64, Flow>` beside the map, or an equivalent).
At `MAX_HELD`, the oldest held dial is evicted: its entry goes, its dial task is aborted (which drops
the mux open and resets it at the relay), and the new SYN takes the place. The evicted app hears
nothing, as when a dial times out, and its SYN retransmit becomes a new held dial. `finish` skips a
cancelled dial task's `JoinError` instead of failing the stack on it. A retransmitted SYN of a dial
still held stays a no-op. The test that pinned "dropped past the cap" is replaced: with 256 dials
stalled, a 257th connection to a live target connects, and the oldest stalled dial was cancelled.

**T-002, no IPv6.** `system::has_ipv6()` is whether `/proc/net/if_inet6` exists (it doesn't when
`ipv6.disable=1` keeps the stack from initializing; the `disable_ipv6` sysctl leaves it there, and
that case already works). `system::families(ipv6)` returns the `ip` family flags to read and flush,
and `snapshot()` and the helper's pin-route flush both use it. `Targets::ipv6_refusal(ipv6)` refuses
an IPv6 CIDR target when the kernel has no IPv6. Preflight adds it to its refusals, and the helper
checks it again as root. Fake v6 already turns itself off when the device can't take its v6
address. New public items only. The README's Limitations section says what `route` does there.

**T-003, a signal during startup.** `Helper::start` stays uncancellable. When it fails, `run` asks
`Signals` whether a signal arrived (`arrived`, which waits a short bounded grace for a signal
already delivered to reach tokio's driver) and returns `Ok(())` if one did. The decision is a small
function tested with a raised SIGTERM, as the existing `Signals` tests do.

**T-004, a remote reset.** `forward::serve` pumps over `&mut socket`. When the pump fails (the
remote reset, or the session went), it sets zero linger before the socket drops, so the app gets an
RST and its read fails with ECONNRESET. A clean close stays a FIN. Tested with a fake tunnel whose
target resets mid-stream, and end to end through the real relay. The README's forward section notes
the difference from `ssh -L`.

**T-005, DNS panics.** In `finish`, a UDP query task that panicked is logged and dropped (its asker
retries). In `served`, a DNS connection task that panicked is logged, and its connection is reset
through the bridge whose pump is that task. Other task failures stay fatal: a panicking dial or pump
is a bug in code the whole stack shares. Tested with a `Dns` that panics on one query.

**T-006, flows.** Both Opening arms (`forward`'s `datagram`, `route::datagrams`' `send`) refresh the
entry with `table.sent` as the Open arm does, so a sender that keeps sending keeps a slow open
alive, as conntrack refreshes an unreplied entry. Paused-clock tests in both. Plus a test of
forward's failed-open branch (the entry goes, and the next datagram opens again), a mixed-operation
test of `FlowTable`'s index invariant, and a nextest override that takes the two `e2e_udp_flood_*`
tests out of retries, with its reason. The comment at forward.rs's Opening-to-Open swap gets fixed.

**T-007, relay.** `nameservers` keeps at most 3 (glibc's and musl's MAXNS), and a link-local v6
server keeps its scope: numeric, or an interface name read from `/sys/class/net/<name>/ifindex`, so
no new `unsafe`. Reading moves into the `spawn_blocking` closure with the file read. `serve`'s body
past the read becomes a private function taking the read's result, unit tested with an empty and an
unreadable resolv.conf, and the vacuous e2e asserts something every machine shares.
`collect_ips` becomes an `unsafe fn` with a `# Safety` section. The unreported-error cap moves to
the documented contract: the 64th in a row ends the flow (the code ended it on the 65th). The two
`.invalid` tests skip on a temporary failure, but fail under `CI` like the client's `skip()`. The
ping e2e fails under `CI` instead of skipping, and the workflow opens the ping range before
`cargo make ci` in the `ci` job and in `codecov`, which runs the same suite. A comment at the query
spawn says what bounds it: the client.

**T-008, mux.** `check_host` and a host-decoding helper replace the inline length and UTF-8 checks
in `frame.rs`. A test that a version-4 Hello with a 10- or 12-byte payload is refused. Doc comments
on `Transport`'s variants and `PeerHello`'s fields.

**T-009, client.** One `fake_v4_of(IpAddr) -> Option<Ipv4Addr>` in `route::names` for the router and
the DNS server's reverse path. DNS-over-TCP tests for a length prefix and body in separate writes and
for a zero-length message. `MAX_DNS_CONNS`'s comment says it bounds tasks, not every socket.

**T-010, xtask.** `write_commit` uses the build script's `COMMIT_FILE` (included with `#[path]`, as
`src/relays.rs` does for its tests), and `package` refuses a tree `git status --porcelain` reports as
dirty, naming the files, so `relays/COMMIT` can't name a commit the tree has left.

**T-011, rust-version and docs.** `rust-version` in `[workspace.package]`, inherited by the three
product crates: the lowest version `cargo +<v> check` passes on, starting at 1.91 (smoltcp 0.14's own
floor). The README's Limitations sentence about administratively prohibited ICMP is split up, and
the Why section's "Milestone 1 builds…" says what the milestones built. CLAUDE.md's Releasing gains
the pre-tag gate (`cargo make ci`, then the UATs of the PRD that ships), and its prose lines past 100
columns are rewrapped.

# Assumptions
- `/proc/net/if_inet6` is absent exactly when the kernel's IPv6 stack never initialized. This is
  from the kernel's `addrconf` init, and the injected tests stand in for a VM boot.
- Aborting a dial task drops its `Mux::open`, which resets the stream at the relay.
- tokio 1.53's `TcpStream` can set zero linger without a deprecated API (`set_zero_linger`, or
  `set_linger(Some(Duration::ZERO))` where that is the current one).

# Constraints
- No public signature changes (0.2.1). New public items are allowed.
- No new `unsafe` beyond turning `collect_ips` into an `unsafe fn`. No new dependencies.
- Linux-only code stays in Linux-only modules: the macOS check in CI compiles every crate.
- No second toolchain in CI (`repo_sync`): rust-version is verified locally, once.

# Non-Goals (MVP)
- Everything the triage drops: the relay's per-flow buffer (about 41 MiB at the cap in practice),
  the DNS edge cases (NODATA vs NXDOMAIN under a fake zone, `dig ANY` on a fake's reverse name,
  address-bearing record types beyond A, AAAA, HTTPS and SVCB, a size guard on rebuilt answers, zone
  transfers), negative caching of refused UDP targets, deduplicating `forward`'s and `route`'s
  Opening/Open handling, splitting `mux.rs` and `stack.rs`, and the theoretical ones. The log gives
  each one's reason.
- PRD-0004 T-014, the bench's occasional stalled round: it stays parked there.
- A timeout of our own on held dials (Q2 chose eviction alone).
- Booting a VM with `ipv6.disable=1` (Q3: the injected test for now).
- The version bump and release: a separate `/ship-it` after this PRD closes.
