# Summary
Milestone 1 proves beachhead's central loop end to end: push a static musl relay over a plain SSH
session, cache it on the remote by hash, exec it, and forward one local TCP port through a
multiplexed stdio channel to a host the remote can reach. There is no TUN device yet. The
milestone also produces a throughput number to compare against `ssh -L`.

# Problem
Remote LAN hosts and names should work from anywhere the way they do at home: the motivating case
is reaching a home-LAN server by its LAN name from a laptop on a hotspot, where `ssh server`
already works (directly at home, through a tunnel away). sshuttle has the
right shape (route a subnet over an existing SSH login) but pipes Python to the remote and depends
on its interpreter. `ssh -D` plus tun2proxy already exists, so beachhead is worth building only if
it beats that on UDP, ICMP, DNS interception and subnet routing. Those arrive in later milestones;
M1 builds the foundation they share and measures its cost.

# Goals
1. The push-exec-cache loop works on a remote with no relay installed and no root: the first run
   transfers the relay, every later run reuses it.
2. `beachhead forward -L 8080:host:80 <destination>` carries TCP end to end, including ~50
   concurrent connections.
3. Flow control holds: memory is bounded by window × streams, and one stalled stream never blocks
   the others.
4. A measured throughput comparison against `ssh -L`.

# Technical Approach

## Layout
- `.`: the `beachhead` package, the client library plus the CLI behind the default `cli` feature.
- `crates/beachhead-mux`: the wire protocol and the multiplexer, shared by both ends.
- `crates/beachhead-relay`: the remote binary, depending on `beachhead-mux` and tokio
  (`current_thread`; `rt`, `net`, `io-std`, `io-util`, `sync`) and nothing heavier. It is a
  separate crate, not a second `[[bin]]`, so feature unification can't drag client dependencies
  into it and the musl build compiles only its tree.
- `[profile.relay]` inherits `release` with `opt-level = "z"`, `panic = "abort"`, fat LTO, one
  codegen unit and `strip`. A custom profile, because per-package overrides can't set `lto` or
  `panic`.
- Both musl triples are listed in `rust-toolchain.toml` `targets`, and `.cargo/config.toml` links
  them with `rust-lld`, which works only while the relay has no C dependencies.
- `cargo xtask relay` builds both into `target/relay/beachhead-relay-<arch>` and writes
  `SHA256SUMS`. The `Arch` table lives once in the `beachhead` lib.
- The trust story, kept as a feature: release builds embed the relays, each release publishes its
  `SHA256SUMS`, and `beachhead relays` prints the arch, sha256 and size of exactly what the client
  would execute on a remote. A new build means a new hash, which doubles as the upgrade path.

## Session flow

```text
client                                    remote (login shell -> sh -c '<script>')
------                                    -------------------------------------
spawn: ssh -T -e none <dest> "sh -c '<script>'"
                                          case $(uname -m) -> expected sha
                                          cached relay-<sha> ok? -> READY, exec
                         <- @@beachhead:SEND <sha> <len>
relay bytes (exactly len) ->              head -c len > staging; size, sha256, --probe
                                          mv into place (atomic) -> READY, exec
                         <- @@beachhead:READY <dir>
                         <- Hello (binary, the relay's first frame)
Hello ->                                  (the client writes nothing between the relay
                                           bytes and the relay's Hello, so head -c can't
                                           over-read into mux bytes)
Open / Data / Window / Fin / Rst <->
```

The client reads stdout lines and skips any without the `@@beachhead:` prefix, because rc files
that echo are sshuttle's classic failure, and it keeps the same `BufReader` across the switch to
binary framing. `ERR` lines abort with the remote's message.

## Bootstrap script
- One line, with no `'`, `!` or `\`: wrapped in single quotes it survives bash, dash, zsh, fish
  and csh as the login shell (csh rejects newlines inside quotes and history-expands `!`; fish
  treats `\` specially inside single quotes). A unit test enforces it.
- Both expected shas are baked in, keyed by `uname -m`. An unknown arch, or no relay for it, prints
  `@@beachhead:ERR`.
- Candidate dirs in order: `${XDG_CACHE_HOME:-$HOME/.cache}/beachhead`,
  `$XDG_RUNTIME_DIR/beachhead` (only when set), `/dev/shm/beachhead-$(id -u)`,
  `/tmp/beachhead-$(id -u)`. The shared-tmpfs dirs are created mode 700 and used only when owned by
  the current user and not a symlink, so another user can't plant a relay.
- A cached `relay-<sha>` is used when it is executable, its sha256 matches (when `sha256sum`
  exists; a few ms) and `--probe` succeeds, which also catches a dir remounted `noexec`.
- On a miss: `head -c <len>` into `.relay-<sha>.$$` in the first writable dir, check size and
  sha256, `chmod 700`, `--probe`, then `mv` into place. A dir that fails the probe (`noexec`) hands
  the staged file to the next candidate. If every dir fails, `python3` copies it into a
  `memfd_create` fd and `os.execve`s the fd (no string literals needed, so the quoting rule holds).
  That path is not cached.

## Mux protocol (`beachhead-mux`)
- Frame header, 9 bytes: `stream: u32 BE | kind: u8 | len: u32 BE`. The decoder rejects
  `len > 64 KiB`, so a garbage length can't allocate. Data chunks are at most 32 KiB, for fairness.
- Kinds: `Hello{magic "BHED", version u16}` on stream 0 in both directions; `Open{port u16, host
  utf8 <= 255}`; `OpenOk`; `OpenErr{reason}`; `Data` (zero-copy `Bytes`); `Window{credit u32}`;
  `Fin` (half-close); `Rst{reason}`.
- `StreamId(u32)`: the client allocates ids monotonically and never reuses one, so late frames for
  a finished stream are ignored.

## Flow control
- **The frame reader never blocks.** It dispatches into per-stream unbounded channels whose depth
  is bounded by credit (a 256 KiB window per stream), so the ssh pipe always drains.
- Send credit is a `tokio::sync::Semaphore` per stream: read up to 32 KiB, `acquire_many(n)`, send
  `Data`. `Window` adds permits; `Rst` closes the semaphore.
- On receive, after `write_all` to the socket, consumed bytes accumulate; at half a window the
  receiver releases them from its outstanding count, then sends `Window(consumed)`. A peer that
  exceeds its credit is reset (a protocol error).
- One writer task owns the outbound pipe and drains two channels: an unbounded control channel
  (`Open`, `OpenOk`, `OpenErr`, `Window`, `Rst`), checked first so credit returns promptly, and a
  bounded data channel (`Data`, `Fin`). `Fin` rides the data channel because it must not overtake
  that stream's queued data. The reader never awaits either channel, which removes the deadlock
  cycle.
- `pump(stream, io)` is generic over `AsyncRead + AsyncWrite + Unpin`, so a smoltcp-backed socket
  slots in for the TUN milestone.

## Tests
- Mux, in process over `tokio::io::duplex`: 50 concurrent echo streams, a stalled stream beside
  live ones, a producer capped by a stalled consumer, half-close, reset, credit violation.
- e2e through a fake `ssh`: a script that ignores options and the destination and runs
  `$LOGIN_SHELL -c "$last_arg"` locally with `HOME` in a TempDir. It covers push, exec and cache
  with no sshd. Root-package tests find the relay binary next to the test executable (cargo builds
  it for `--workspace`) and stage it in a `--relay-dir`.
- Throughput: an `#[ignore]`d test that starts a throwaway non-root sshd on a free port with temp
  keys and compares `beachhead -L` against `ssh -L`.

# Assumptions
- The remote is Linux on x86_64 or aarch64 with a POSIX `sh`, `uname`, `head -c`, `mkdir`, `mv`
  and `chmod` (GNU, busybox and toybox all qualify).
- `ssh <destination>` already works non-interactively, or prompts on the tty, never on stdout.

# Constraints
- No crates.io publish or release tag until Aaron confirms directly. The GitHub repo is public
  (Aaron's call, 2026-10-15), so nothing personal (hostnames, addresses, paths) goes into it.
- The relay must not grow C dependencies while it links with rust-lld.
- Known limits for the README: musl's resolver reads only `/etc/hosts` and `/etc/resolv.conf`, so
  the systemd-resolved stub works but mDNS (`.local`), LDAP and NIS names don't resolve through the
  relay; the memfd fallback is defeated by `vm.memfd_noexec=2` (Linux 6.3+).

# Non-Goals (MVP)
- TUN, smoltcp and subnet routing (M2); DNS interception (M3); UDP and ICMP.
- Remote-to-local (reverse) forwards and reconnecting a dropped session.
- Compressing the relay on the wire (SSH compression usually covers it) and a Perl memfd fallback
  (syscall numbers differ per arch).
- Wasm on the remote (no runtime there, and WASI preview1 has no sockets).
